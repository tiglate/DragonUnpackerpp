# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Dragon UnPACKer++ is a game-resource explorer/extractor (MPL 2.0): a C++20/Qt 6 port of Dragon UnPACKer by Alexandre "Elbereth" Devilliers (original author), ported and extended by Tiglate Pileser III. Keep these credits in README.md and the About dialog. The repository has these parts:

- `app/` — **the Qt 6 interface (C++20, CMake)**: the only GUI of version 6 (the Lazarus GUI was removed).
- `driver/` — **the format driver, C++20**: a shared library with a plain C ABI ("DUDI 7") holding every format (131 registered, all of v5 except the ones listed in `docs/FORMATS_TO_VALIDATE.md`); `contract/` (C header `dudi7.h` and `DUDI7.md` with the rules), `cpp/` (the library, CMake), `tools/` (`dudi7cli`, used by the tests), `tests/`.
- The original **v5** (Delphi 7, Windows only) sources were removed from the tree once everything that made sense was ported: they are in the git history, tag `legacy-v5` (`git show legacy-v5:legacy/v5/plugins/drivers/default/drv_default.dpr`; the format code of the C++ driver says which v5 unit it comes from).
- `docs/` — `MIGRATION.md` (status and pending items: keep it updated), `docs/UI_REDESIGN.md` (design and phase results of the Qt interface), `manual/` (LaTeX manual).

`README.md` is the user-facing description; this file is for working on the code.

## Building

- `./make.sh <action>` (and `make <action>`, a proxy to it; extra arguments via `ARGS=`): `build [all|driver|ui|cli]`, `rebuild`, `run -- <app args>`, `test`, `test-driver`, `test-ui`, `e2e FILE...`, `sweep DIR...`, `bench FILE`, `list`, `extract`, `configure`, `clean`, `purge`, `declutter` (removes the Python caches), `install -p DIR`, `package`; `./make.sh --help` lists them.
- **Driver** (C++20, CMake + Ninja, zlib; Linux x86_64): `./make.sh build driver` gives `build/plugins/libdrv_default.d6d.so` and the test tool `build/tools/dudi7cli` (`build/` at the repository root, build tree `build/cpp/`; the Qt build tree is `app/build/`). No third-party code is needed beyond zlib.
- **Interface**: CMake + Ninja, Qt 6.4 Widgets/Multimedia/Svg/LinguistTools, spdlog, Microsoft GSL (see the Qt section).

## Architecture (driver, `driver/`)

v6 drivers use **DUDI 7**, a plain C ABI (cdecl exports, fixed-width ints/pointers/UTF-8 strings only, `int32_t` status returns and never exceptions, plugin-owned strings, opaque archive handles, host callbacks with a `ctx`, no plugin UI; legacy v5 `.d5d` plugins are intentionally not supported). The contract is `driver/contract/dudi7.h`; `DUDI7.md` has the rules (the driver itself was ported from Pascal to C++20 and the Pascal sources are gone: `git log` has them, the last commit with the Pascal driver is the parent of "C++ driver: switch over").

- Host side: the Qt interface (`app/src/Dudi7`, `app/src/Core/DriverHost`) loads `plugins/libdrv_default.d6d.so` (Linux; `drv_default.d6d` on Windows) or `$DUP_PLUGIN`. `driver/tools/dudi7cli.cpp` is a minimal host (dlopen) used by the tests.
- `driver/cpp/src/Reader.h` (cached file or in-memory reader, `Error` for DUDI7 statuses, `ReadError` for truncated reads), `Archive.h` (base class: `Add`, `Fail`, `CheckTable`, `ExtractZlib/Deflate/Bytes`, `Unpack` for compressed directories, `DecodeChunk`), `Registry.h` (`Register<T>(extensions, name)`), `Exports.cpp` (the C ABI, no exception crosses it), `PathUtil.h`.
- One file per format in `src/formats/`: a class deriving from `Archive` with a static `Check(Reader&)` (and `RequiresExtension()` if there is no reliable signature: such formats are only tried on files with a registered extension) and `Parse()` (fill the entries with `Add`), plus a `Register<Name>()` function listed in `src/FormatList.inc`. **The order of `FormatList.inc` decides which format claims a file** (it is the order of the original Pascal driver). Decoders are in `src/codecs/` (RNC, LZO, LZMA, LZ4, LZX, crunch, ETC/EAC/BC, ASTC, Vorbis to Ogg, the FSB codebook table, the Unity serialized-file reader/exporter/mesh writer). `driver/cpp/CMakeLists.txt` globs `src/formats/*.cpp` and `src/codecs/*.cpp`. v5 code (`legacy/v5`) is the reference for the on-disk layouts of the formats not ported yet.
- Pitfalls: `Check` must validate enough not to claim files of other formats (signature-less formats: `RequiresExtension` plus a full table check; run `driver/tests/sweep.py` and `fuzz.py` after adding a format); loop counters wider than the table size (`uint32_t` counts, never `int` for a 32 bits count; a table of 0 entries must open: `zero_entries.py`); fixed `char name[N]` buffers are not null terminated (`ZString`); `Fail` is `[[noreturn]]`; 64 bits sums of values read from the file can overflow (wrap them explicitly, see `Sum`/`Add64`); no mutable state shared between archives (the host calls the driver from several threads, one archive handle per thread, no globals); encrypted data: set `_extractInternal` and override `DecodeChunk`; compressed entries: override `Extract` and use `ExtractZlib/ExtractDeflate/ExtractBytes`.
- Unity: UnityFS bundles (`UnityFs.cpp`) and stand-alone serialized files (`UnityAssets.cpp`) share `UnityObjects.cpp` (textures as TGA/DDS, sounds, texts, fonts, cubemaps, sprites, meshes as OBJ); `codecs/UnitySerial` reads the serialized files with their type trees, or with the built-in layouts of `unity_trees.json` (generated into `codecs/UnityTrees.inc` by `tests/gen_unity_trees.py`) when the trees were stripped; independent python reference: `tests/unity_ref.py` (used by `verify_real.py`). FMOD `.fsb`/`.bank` are in `Fmod.cpp` (Vorbis becomes Ogg with `codecs/VorbisOgg` + the setup table `codecs/FsbCodebooks`, packed data generated by `gen_fsb_codebooks.py`; independent reference `tests/fsb_ref.py`), XNA `.xnb` in `Xnb.cpp` (LZX/LZ4 compressed content, textures, sounds, effects, SpriteFonts as atlas + BMFont `.fnt`).
- Console ROMs: `formats/Nes.cpp`, `Snes.cpp`, `MegaDrive.cpp` derive from `RomArchive` (`codecs/RomGfx`: `RomSource` gives the logical ROM, deinterleaving `.smd`; entries are raw parts, text, tile sheets as 32 bits TGA, or `Decoded` streams). `codecs/RomCompress` has the Nemesis/Kosinski decoders (checked against the mdcomp reference logic), the Nintendo LZ decoder (SNES, three spellings), the Final Fantasy VI LZSS and Chrono Trigger's packet LZ (`DecodeLzPackets`) and the scanners `ScanMegaDrive` / `ScanSnes`; `codecs/Brr` decodes the SNES BRR samples to WAV and scans for them (`RomArchive::AddBrr`). `codecs/Palette` finds the palettes (Mega Drive, SNES, NES) and `RomArchive::AddPalettes` lists them as `palettes/*.pal` + swatch; the tile sheets are colour mapped TGA (`DecodeTga(data, palette)` in the app replaces the map: `PreviewRequest::PaletteEntry`, `MainWindow::SetPreviewPalette`, `--palette=NAME`). `tests/verify_roms.py` + `tests/rom_fixtures.py` test them.
- Tests (`driver/tests/`): `run.sh` runs a C harness (`harness.c`, proves the ABI is plain) against synthetic fixtures from `make_fixtures.py` (one per format: add yours there and in the harness table). `fuzz.py` mutates the fixtures and checks every answer is a clean status (generic error -1 = a bug). `run_all.sh` adds the decoder checks (`verify_lzo.py`, `verify_lzma.py`), `zero_entries.py`, `verify_real.py` on the Unity/FMOD/XNA fixtures and `verify_texdecode.sh` (needs `pip install texture2ddecoder`). `run_real.sh <files...>` lists real archives with `dudi7cli` and compares names/offsets/sizes/MD5 with the independent python reader `verify_real.py`. `sweep.py` is the false-positive sweep on a game library. Game files exist under `~/.local/share/Steam/steamapps/common/` and `~/gog`; copy to /tmp before testing (`run_real.sh` does).

## Qt interface (`app/`)

C++20, CMake + Ninja (mold and ccache when installed), Qt 6.4 Widgets + Multimedia from the distribution, spdlog, Microsoft GSL, Boost.DI (vendored single header `src/ThirdParty/di.hpp`, doctest in `src/ThirdParty/doctest.h`). Plan, decisions and per-phase results: `docs/UI_REDESIGN.md`. Style as in `Abuse_2025`: clang-format Microsoft, PascalCase types and methods with trailing return types, `_camelCase` members.
- Layers: `src/Dudi7` (dlopen wrapper + RAII `Driver`/`Archive` over the C ABI; failures throw `Dudi7::Error`), `src/Core` (pure C++20, no Qt: `EntryNames`, `ArchiveIndex`, `Extractor`, `ExtractionJob` (thread), `PreviewWorker` (thread), `AppSettings`, `DriverHost`, `TgaDecoder`, `DdsDecoder` + `Bc7Tables.h`), `src/Ui` (Qt: models, `MainWindow`, `JobsPanel`, `PreviewPanel`, `ImageViewer`, `ThemeManager`), `main.cpp` is the Boost.DI composition root. Keep Qt types out of `Core`.
- Threading rule: **one archive handle per thread** (the extraction job and the preview worker each open their own); the driver is written to allow it (no global mutable state). GSL `Expects` terminates the process: do not use it for conditions a caller can trigger (stale entry numbers).
- Command line hooks (tests): `dragonunpacker [--plugin=F] [--settings=F] [--theme=dark|light] [--open=F] [--folder=a/b] [--select=NAME] [--recursive] [--sort=COL] [--extract-all=DIR|--extract-selected=DIR] [--screenshot=F.png] [--quit]` (with `-platform offscreen` no display is needed; with `--quit` no modal dialog is shown), `--benchmark=FILE` (no window).
- Build/test: `./make.sh build ui`, `run -- <args>`, `test-ui` (ctest: doctest suite with the driver's fixtures, thread test of the driver, UI smoke tests), `e2e FILE...` (extract and compare MD5 with the driver listing), `bench FILE`. Independent decoders for checking image code: a venv with `texture2ddecoder` and `pillow` (see docs/UI_REDESIGN.md section 12).
